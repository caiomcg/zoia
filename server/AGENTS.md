# server/AGENTS.md

The Node app: accounts, LiveKit tokens, chat, schedule and the addon API. Root
[AGENTS.md](../AGENTS.md) holds the invariants; most of them live in this folder.

## Layout

| Path | Holds |
|---|---|
| `src/index.js` | Express app, routes, middleware wiring |
| `src/config.js` | Env parsing and validation, fail-fast on startup |
| `src/accounts.js` | Accounts: email, password, role, approval, reset and claim codes |
| `src/devices.js` | One credential per machine signed in to an account |
| `src/database.js` | The SQLite database: schema, migrations, transactions, JSON import |
| `src/stores.js` | Opens the database and every store in it, for the server and keytool |
| `src/token.js` | LiveKit AccessToken minting — subscribe-only, always |
| `src/stage.js` | Who may broadcast, and who is in voice, right now — **the security boundary** |
| `src/idle.js` | Disconnecting a machine from its channel, and the idle sweep (ADR 0037) |
| `src/chats.js` | The text chats and how many there may be (ADR 0036), in SQLite |
| `src/messages.js` | Chat messages, read markers, replies and mentions, in ScyllaDB |
| `src/chat-routes.js` | The chat API and its live SSE stream; `resolveChat` and `tell` |
| `src/chat-media.js` | Chat photos and videos on disk, typed by their bytes, under one cap |
| `src/direct-chats.js` | Direct messages: one private chat per pair of accounts (ADR 0047) |
| `src/schedule.js`, `src/schedule-routes.js` | Scheduled events, RSVPs, the sweep that announces starts (ADR 0050) |
| `src/addons.js` | Installed addons: manifests, permissions, settings, commands, chats (ADR 0041) |
| `src/addon-routes.js` | The addon API, `/api/addon/v1`, every route behind one permission |
| `src/addon-admin.js` | The super admin's addon routes: install from GitHub, enable, settings |
| `src/scylla.js` | Connects to ScyllaDB, creates the keyspace, applies its schema |
| `bin/keytool.js` | CLI on the server: the super admin, reset codes, devices, backups |
| `public/` | The static landing page. Plain ESM, no build step, no framework |
| `data/zoia.db` | Every credential and identity (ADR 0032). Gitignored, never deployed over |

`public/vendor/` is generated by `npm run vendor` (run by `npm start`, `npm run dev` and the
Dockerfile) and is not committed.

## keytool

```bash
npm run keytool -- account:super <email>                 # the one super admin (ADR 0031)
npm run keytool -- account:list
npm run keytool -- account:reset <id> --codes <path>     # for an admin nobody can reset
npm run keytool -- device:list [accountId]
npm run keytool -- device:revoke <deviceId>
npm run keytool -- db:backup <path>                      # consistent copy while running
```

## Adding a route

- Admin route: re-read the caller's role from the database in the handler (invariant 4).
- Anything taking a chat id: go through `resolveChat`; anything emitting a chat event: go
  through `tell` (invariant 10). Add a case to `test/messaging.test.js`.
- Addon route: exactly one permission, re-read per request; strip emails, hashes and
  credentials from the response (invariant 7). Document it in `docs/addons/api.md`.
- Log ids, never emails or secrets (invariant 2).

## ScyllaDB

A deleted chat message frees its space at the first compaction after `gc_grace_seconds`, which
the messages and reactions tables set to an hour (ADR 0042). That is only safe because the
keyspace has **one replica**: give it more and the setting must go back to at least the repair
interval, or deleted messages come back.
